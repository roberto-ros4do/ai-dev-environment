# AI Dev Environment

> Um diário de aprendizado sobre engenharia de software assistida por IA, construído a partir de desafios reais de desenvolvimento.

## Sobre esta jornada

Este repositório acompanha minha evolução no uso de IA durante o desenvolvimento de software. O objetivo não é apenas aprender ferramentas: quero entender como organizar contexto, melhorar fluxos de trabalho, integrar ferramentas, automatizar verificações e avaliar os resultados dessas mudanças.

Parto de uma rotina em que utilizo IA conversacional para discutir requisitos, implementar funcionalidades e orientar auditorias, enquanto desenvolvo em um editor de código. O próximo passo planejado é avaliar uma migração gradual para Claude Code, depois da conclusão e estabilização do MVP profissional em que trabalho.

Este é um **diário de aprendizado**, não uma coleção de soluções prontas. Vou registrar o que estudei, as dúvidas que surgiram, decisões tomadas, dificuldades e resultados observados — inclusive quando algo não funcionar.

## Objetivos

- Entender os fundamentos de AI Engineering aplicados ao desenvolvimento de software.
- Melhorar a qualidade e a previsibilidade do trabalho assistido por IA.
- Aprender Context Engineering e organizar instruções persistentes.
- Explorar Claude Code, skills, hooks e MCP com propósito definido.
- Evoluir auditorias manuais para processos verificáveis e testes automatizados.
- Investigar agentes, workflows e, quando fizer sentido, RAG.
- Desenvolver critérios para avaliar benefícios, limitações, custos e riscos das soluções.

## Ponto de partida

Atualmente, meu fluxo envolve:

1. Descrever requisitos, regras e casos de exceção para a IA.
2. Solicitar análise dos padrões existentes antes de implementar mudanças.
3. Revisar o comportamento das funcionalidades por diferentes perfis e cenários.
4. Executar verificações predominantemente manuais, apoiadas pela IA.

Quero evoluir esse processo de maneira incremental, sem comprometer a estabilidade do projeto em produção.

## Escopo e privacidade

Este repositório é pessoal e público. O ambiente profissional é uma fonte de problemas e aprendizados, **não de código ou dados para publicação**. Não serão incluídos segredos, informações de clientes, código proprietário, capturas internas nem detalhes sensíveis. Exemplos futuros serão independentes e fictícios, quando necessários, e sua publicação deverá respeitar as regras da empresa.
